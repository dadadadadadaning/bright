## 3. 约91%的相容度受到背景查询主导

软相容度为“真实区域软标签·检索加权软标签”，是两个四类分布的点积。查询真实标签仅在检索及预测固定后用于评分。这个量不是像素 accuracy、建筑 Recall 或检索正确率。

| 查询分组 | 查询数 | 占全部区域查询 |
| --- | ---: | ---: |
| 前景纯净 | 58737 | 12.75% |
| 前景混合 | 2253 | 0.49% |
| 背景稀释 | 23342 | 5.07% |
| 大部分背景 | 376468 | **81.70%** |

这些是区域查询比例，不是像素、图片或建筑比例。代码中大部分背景指前景比例低于20%；前景纯净要求前景比例至少80%，且前景内部主类比例至少80%。混合标签自然限制分布点积上限，因此33%–35%不能读成只有三分之一分类正确。

## 7. 下一步只有一条顺序

**一次现成结果汇总 → 一次固定库区域证据控制 → 一轮匹配的可拒绝 Reader。** 不继续增加历史重放前置步骤。

首先把独立 SUMMARIZE_MEMORY_REBUILD_V3.py 放在服务器 New/，用默认已完成根目录运行：

```bash
/root/shared-nvme/conda-envs/bright4090/bin/python /root/shared-nvme/BRIGHT-master/New/SUMMARIZE_MEMORY_REBUILD_V3.py
```

它只读 JSON，输出四组类别归一化相容度/覆盖、两个 Top64 的每类 rescue/harm/net TP/delta FP、各事件基线与两候选差值。只验证小型元数据完成状态与绑定，不重新校验大 bank、权重、全部预测文件或数据；缺项 N/A。

rescue 是基线判错而候选判对；harm 是基线判对而候选判错。两种百分比的分母不同，不能直接相减；净 TP 还需结合 FP 才能理解 IoU。rescue 大于零只说明有纠错案例，随机投票也可能偶然纠错。不要要求裸投票净收益必须为正才允许 Reader，拒绝门就是为了减少 harm。

随后只做一次固定库的区域证据控制：T128/F256 Top64 的真实检索、固定种子的跨事件随机支持、打乱支持标签，保持 K、温度、事件排除、查询一致。优先报告 Damaged/Destroyed 的归一化证据及逐事件差异，避免背景主导；不反复调 K/温度寻找通过结果。已保存 FP32 query、支持成员与事后软标签可支持 CPU 区域证据控制，不需新的前向。**缓存未保存 Q 与路由 ids，不能据此直接生成新控制的像素 mIoU。** 像素级控制留在 Reader 阶段做。

有跨事件、超过随机/打乱控制的损毁证据时，进入 E2：query-only、T128 Memory、F256 Memory 三组。若证据弱，只选择支持覆盖或检索距离中的一个问题修复。控制结果用于确定 Reader 值得尝试的证据，不要求所有类别或每个事件都获益。

Reader 使用 grid_probq 为基底；三组固定同容量、同初始化、同训练图像流、同采样/损失、同预算、同 Val 选择规则。Memory 两组使用同一支持 value 定义，仅改变检索 key，先固定 Top64。纠错分支零初始化，空支持回退，拒绝门只读部署时可获得的特征、预测不确定性、相似度和支持证据。Train 查询也排除同图/同事件，查询真实标签只用于监督或事后评分。

主要验收是 Memory 同时超过 grid_probq 与同容量 query-only，并对真实支持/标签有依赖；结合随机、打乱、关闭支持，报告损毁类、逐事件和误改。V3 仅有建库诊断，Reader 需独立 E2 实现；不要把旧版训练命令当作新库 Reader 的已实现阶段。

本轮不同时加入新 Q、多原型、建筑加权或 SAR 专用投影。跨事件支持排除不等于主干对从未训练过的事件泛化；整体框架新闻分数和不同类别平均口径也不能直接与本次前景 mIoU 相减。
