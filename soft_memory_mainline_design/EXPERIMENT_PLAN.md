# Soft＋Memory 研究主线：实验、图示与结果解释

版本：2026-10-16。依据上传的《新图.pptx》、当前 `soft_memory_q_rebased_v1_fix2` 实现及对话中已披露的实验状态。原 PPT 不修改；原表格数值不用于本设计。本文是待执行的研究协议，不是新实验结果，也不是训练启动器。

## 1. 把主线写成可检验的问题

**研究问题：在保留像素细节和 Q 概率共享的基础上，建筑概率引导的双槽区域组织，是否能让分类器更有效地结合图内证据与 Train 历史案例，判断建筑损毁？**

三项需要分别回答的主张：

1. 区域内分开组织偏建筑、偏背景的证据，是否比匹配的空间双槽更好？
2. 历史案例是否比相同结构的图内参考提供额外价值？
3. 组合方案是否在相同来源、相同训练规则下，稳定超过基础预测和强对照？

把 soft＋Memory 作为研究主线是合理的，但不能把“D 一定最好”当作前提。若重复后 C 好于 D，应报告这套 soft 组织没有带来额外收益。若 D 只比 A/B/C 好、仍低于基础预测，也不能称最终系统已经进步。

“减少背景混合”“改善 Damaged”“建筑实例一致性”“正协同”是四种更强的机制主张，分别需要对应证据，不能仅凭平均分上涨一并宣布成立。

论文贡献应落在“建筑概率双槽的一致汇总/标签/回投，以及像素、父区域和案例的联合读取与验证”。超像素、历史案例检索和cross-attention本身已有研究，不能把模块名称的组合直接称为首次提出；具体原创性仍需与相关方法逐项核实。

## 2. 当前实现究竟是什么

### 2.1 保留的基础

- 冻结 A1、当前 Q 来源以及父区域表示生成过程。
- 保留完整 F256 像素特征通路。
- P0=`grid_probq`：先得到位置类别概率，再由 Q 汇总并回投。
- 父区域表示同时保留 Q 加权 F256 均值与复杂父 token T128。

这轮使用重建后的 Q-baseline 来源。旧 E0 的 `grid_probq`、旧 soft 以及旧 R0/RT/RF 可作历史背景，不能填入本轮表格作为同源消融。P0 必须在本轮相同配置下重新计算。

### 2.2 新增 soft 组织

令 i 表示特征位置，k 表示父区域，B_i 为模型预测建筑概率：

```text
w(i,k,0) = Q(i,k) × (1−B_i)
w(i,k,1) = Q(i,k) × B_i
w(i,k,0) + w(i,k,1) = Q(i,k)
```

每个槽分别按自己的 w 汇总 F256；父 T128 作为上下文保留。槽角色不是真实类别：偏背景槽仍能包含被漏检的建筑和 Damaged 证据。

Train 支持软标签必须按同一 w 汇总四类有效标注。特征按槽总质量归一化，标签按有效标注质量归一化；ignore 像素不可变成背景。空槽用有效性 mask 标记。

父区域按原 Q 回投；子槽特征和读取的 Memory context 按各自 w 回投。不能把两槽各自完整用 Q 回投，造成贡献重复。

当前方法不区分真实建筑实例，不保证区域连通，也没有保证“不跨邻楼”。准确叫法是“固定软区域分配下的建筑概率双槽组织”。若论文保留“超像素”称呼，方法中应交代软分配形式及连通性限制。

### 2.3 检索与读取分开

1. 用父 T128 key 查找 Top64 合法父案例。
2. 每个父案例展开最多两个有效槽，最多128个槽；仍然只有64个父案例。
3. 支持槽包含 F256、父 T128、槽角色、质量占比、有效性，以及四类软标签。
4. 特征产生注意力 K；V 额外引入标签信息。两个查询槽都可读取全部合法候选槽，不限制同角色配对。
5. 当前 Reader 是多头注意力和 context projection；空支持 context 为零。

事件和图像身份用于排除与审计，不应画成当前 Reader 已使用灾害类型 embedding。查询的 Val/Test 真值不进入路由、检索或 Reader。

### 2.4 最终联合分类

```text
像素F256、父区域、双槽、Memory回投、P0 → 非线性联合分类头 → Δ
最终概率 = softmax(log(P0) + Δ)
```

联合头末层零初始化，使初始预测等于 P0。此处是训练起点，不是 Memory 的采纳阈值或拒绝门控。模型训练后共同利用全部通路。

## 3. 第一优先级：完成已有训练退化诊断

先读完已经启动的固定 Train/Val 诊断，不再增开一套区域结构。

使用已保存的500、1500、5000步权重，固定前端、完整推理方式、训练损失公式和归一化，在同一固定 Train 子集与 Val450 上计算：

- loss、前景三类 mIoU、各类 IoU；
- Damaged precision/recall、Damaged→Intact/Background 混淆；
- Intact 原正确→错误的数量；
- 逐事件差值；
- 相对 P0 的 logits 修正量、预测类别占比，可用于发现持续偏离基础预测。

Train 查询检索仍排除同图、同事件。Train/Val 使用一致的 eval 设置，避免把训练增强、dropout 或不同损失权重造成的差异误读为泛化差距。单步训练 loss 对应不同图像，不能代替固定 Train 评估曲线。

| 观察 | 支持的方向 | 还不能直接断言 |
|---|---|---|
| 固定 Train 持续改善，Val 持续变差 | 泛化差距扩大，支持过拟合解释 | 唯一原因一定是模型容量 |
| Train 与 Val 都下降或强烈波动 | 优先检查优化、学习率、图像/事件顺序和损失计算 | 必然是过拟合 |
| loss下降，但Damaged IoU下降 | 检查类别权衡、校准和损失与指标不一致 | Reader完全没用 |
| 只少数事件下降明显 | 检查域差异、案例覆盖和事件权重 | 所有区域设计无效 |
| 三个检查点重复推理不一致 | 先修复评估/数值与状态问题 | 模型结构导致成绩变化 |

根据诊断选择一次明确的训练方案，再对所有组一起使用。不要给 D 单独选最优学习率、给 A/C 沿用旧配置。

**短训练的代码陷阱：**当前 `_lr(step, steps, ...)` 由总 steps 决定 warmup；5000步日程的warmup为500步，改为500步日程则warmup为50步。因此“总步数设500”不等于“原5000日程截取前500步”。应分别记录学习率日程长度与停止步数。当前正式入口还要求5000更新；新短训练协议需要新增合法入口，不能声称现有 `--steps 500` 已支持。

原500步候选来自观察后的选择，应记录为探索发现。若随后预先固定500步开展新种子重复，可以验证复现性，但不能把之前的选择写成事先注册。不要继续用已经看过的 Test500 结果选择结构、步数或种子。

## 4. 必做主实验：A/B/C/D 的配对重复

四组共同使用新Q来源、相同P0、相同像素/父区域/联合头、Top64父参考、同一训练图序、初始化、优化器、loss、更新预算和最终模型选择规则。

| 组 | 槽组织 | 参考来源 | 参考标签 |
|---|---|---|---|
| A | 固定空间棋盘双槽 | 当前图像的区域近邻（包含自身） | A1预测概率按槽汇总 |
| B | 建筑概率soft双槽 | 同上 | 同上 |
| C | 固定空间棋盘双槽 | Train历史案例 | Train真值按槽汇总的软标签 |
| D | 建筑概率soft双槽 | 同上 | 同上 |

“固定空间”在当前代码中是4特征格的硬棋盘分组。A/B和C/D有相同网络形状，但连续性、槽质量分布和有效槽数可能不同。记录实际非空槽数、质量分布、参数量、运行时间和显存，不能声称全部有效容量完全相同。

建议至少3个配对训练种子。每个种子内四组共享初始化和图像顺序；种子之间允许正常变化。对应12个组别×种子结果，并不要求同时启动12个GPU任务。冻结前端前向可以共享，但优化器与梯度隔离必须明确。

先固定案例成员与库，仅改变Reader训练种子；因此该轮不检验“重新抽取案例库”的不确定性。如后续声称库采样稳健，再单独重复成员采样。

### 必须报告的差值

```text
B−A：图内条件下，soft整套分组规则相对空间分组的收益
D−C：Memory条件下，soft整套分组规则的收益
C−A：空间分组条件下，历史标注参考相对图内参考的收益
D−B：soft条件下，历史标注参考相对图内参考的收益
D−C−B+A：两项改法在mIoU尺度上的交互量
D−P0：完整系统是否优于同源的基础预测
```

其中Memory差值包含“参考来源、标签信息和检索方式”的整体变化，不能仅凭D−B宣称余弦检索排序或Train标签单独有效。

**组合实用性与正交互是两件事。**D稳定高于B/C且超过P0，支持组合有实际价值；若还要写“超过简单相加的协同”，交互量本身也需稳定为正。不能要求任意一次微小正差值就算稳定。

## 5. 消融按论断选做，避免无目的地堆组

### 5.1 若要声称双槽比单槽更好：新增同源单槽对照

- S-local：当前Q下，单槽＋图内参考。
- S-memory：当前Q下，单槽＋历史案例。

两组从同一新Q来源重新训练，使用同一选择规则与预算。旧R0/RT/RF不可以代替。

报告真实参数量和读取token数。双槽64父案例最多128槽，单槽64父案例64槽，结果是结构与读取信息量共同变化；不能把它包装成精确相同信息容量。可进一步用共享编码器、相同Reader维度和受控token预算检验，但不要为控制参数而人为提供额外独立案例。

### 5.2 若要声称建筑位置引导有效：连续错位B对照

- D-shiftB：仅对槽路由使用的B进行预先固定的空间平移；连续概率值和整体分布保留，建筑位置对应关系受扰动。
- 前端原有建筑调制和Q不变；查询与Train支持的槽特征、标签、占比都按相同新规则重新生成。
- 与D同预算重新训练；必要时在B分支也加入对应对照。

它能减少“只是硬分组变成连续分组”的解释。边缘使用何种平移/循环规则需固定，并记录；错位实验不是完美的纯语义因果实验，应配合背景混合与低B分层结果。

### 5.3 若要声称检索找到了有用案例：随机合法父案例

- D-random：同样的64个父参考预算、同图同事件排除、有效性规则；随机选择合法案例，保留案例与真实标签的正确对应。
- 最好与D匹配训练。随机种子、采样频率与合法候选不足时的填充规则预先固定。
- D优于D-random支持检索选择比一般历史参考更有价值；不是只证明增加网络参数有用。

### 5.4 若要声称历史标签被有效利用：移除/置换标签

- D-noLabel：候选和支持特征不变，标签输入固定为零，保持网络接口与其它配置；匹配训练。
- D-shuffleLabel：固定置换支持成员的四类软标签（保留分布及空槽规则），破坏特征与标签对应，用于进一步检验对应关系。

对已训练D仅推理时换随机邻居或打乱标签，是便宜的敏感性检查；性能下降可能包含输入分布改变，不能直接替代匹配训练消融。

### 5.5 若要声称像素细节保留有效

- D-noDirectPixel：仅移除直接F256像素分支，保留其它路径并重新训练。
- 因P0、父区域和支持仍源于像素，图表必须称“去掉直接像素特征分支”，不能写“无像素信息”。
- 在边界和小前景连通块上评估。若没有真实实例ID，不能把连通块统计叫作逐栋建筑统计。

Top8/Top64、T128/F256检索、SAR→Q、重新选库、额外语义损失不属于首批必跑消融。主线站稳后再按结果选择。改Q后必须配套重建查询与支持，不可只改一侧。

## 6. 最小实施顺序

| 阶段 | 任务 | 通过后可以说什么 |
|---|---|---|
| 0 | 完成固定Train/Val的500/1500/5000诊断 | 缩小训练退化原因；尚非新结构收益 |
| 1 | 冻结一个训练/选模协议，重跑A-D的配对种子 | soft和Memory在同源条件下是否各有增量 |
| 2 | 加S-local/S-memory；验证最关键机制消融 | 双槽、建筑引导、检索/标签各自的证据范围 |
| 3 | 整理同ID案例与失败图、成本和逐事件差异 | 说明收益发生在哪里及其限制 |
| 4 | 固定最终方案后做统一Test报告 | 最终泛化表现；披露此前探索性Test500 |

若阶段1仍没有系统增益，先根据阶段0和机制结果修训练/表示，再重复；不靠追加SAR、扩大区域或隐藏负对照维持“D必须有效”的结论。

## 7. 评价与结果表

主指标：对整个split汇总混淆矩阵，再计算Intact、Damaged、Destroyed三个IoU的均值。背景参与预测，但不计入该前景平均；四类mIoU若另报，明确区别。

论文主结果表与内部消融表分开：主表可包括同协议的原像素A1、P0、最强图内分类对照、所选完整方案，以及能够在相同BRIGHT划分和指标下核实的代表方法。消融表专门放A/B/C/D与结构/检索对照。公开论文的不同split、不同类别平均、实例AP或不同训练数据成绩不能直接混成一张排名；新增组件消融应固定前端，完整系统与外部方法比较则准确列出各自训练条件。

每张主表至少给：

- 前景mIoU、三类IoU、Damaged precision/recall；
- 相对同源P0和匹配对照的差值；
- 训练种子均值±标准差，逐事件配对差异；
- 参数量、GPU峰值显存、固定硬件下推理时间，区分一次性建库成本；
- Q来源、库成员版本、训练终点/选模规则、有效参考数量。

不要把几十万个像素当作独立重复样本计算极小误差条。验证集不确定性可使用配对图像/事件聚类bootstrap；训练不确定性由配对种子评估，二者分开报告。逐事件均值不等于split整体mIoU。

| 结果形态 | 推荐说明 |
|---|---|
| D高于B/C/P0且跨种子稳定 | 支持该条件下soft与历史参考共同改善系统 |
| D高于B，但不高于C | 历史参考有价值；新增soft尚无额外支持 |
| B高于A，D约等于B | 图内soft有效；Memory增量不足 |
| D是四组最好，但低于P0 | 新结构相对消融较优，尚未改进基础系统 |
| 只有某个中间检查点好 | 记录为探索候选，需固定短训练协议重复 |
| mIoU提高但Damaged下降 | 报告类别取舍，不能宣称受损/稀有类别全面改善 |

没有可诚实保证的目标分数。预期应写成可检验方向及稳定性标准，而不是预填“提升1–2个百分点”。小幅收益需要比大幅收益更谨慎地排除种子、选模及事件组成影响。

## 8. 需要哪些案例图

### 图1：总体预测对照

RGB、SAR、GT、P0、A、B、C、D。所有列使用同图同裁剪同尺度，统一四类颜色。若一页过密，把输入/预测拆成两行，不缩成无法辨认的缩略图。

预先定义分层，至少覆盖soft正例、Memory正例、普通中位例、原正确被改错、C优于D失败、低B建筑、小前景/边界、不同损毁邻楼。可从Val开发集选6–8个跨事件案例，但数量仅是排版建议，不构成统计证明。

显示B连续概率、父Q展示图、w0/w1、前景/类别混合程度，以及B−A和D−C的救回/误伤。

Q的argmax着色只是方便展示软区域归属，不能标成真实建筑边界。混合度下降是诊断线索，不自动证明它导致最终性能上升。GT只用于事后分析。

显示一个真实查询、两个槽、实际选中Train父案例的前4/8名缩略图。每例标注rank、图像/事件ID、相似度、四类软标签条、槽有效性和两查询槽的读取权重（若导出）。明确“完整候选64，图中仅展示前若干”。

分别展示一次有用检索和一次相似外观却标签不匹配的失败。注意力高不等于案例贡献已被证明，需要配套干预。

### 图4：训练退化

固定同一裁剪比较500/1500/5000步，并放固定Train/Val loss、类IoU和Damaged混淆曲线。展示完整轨迹，不能只给最好时刻。

### 图5：总体可靠性
