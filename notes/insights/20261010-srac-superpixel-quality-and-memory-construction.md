# SRAC：超像素质量、检索错误与 Memory 建库的分离诊断

日期：2026-10-10。研究任务：BRIGHT 灾前 RGB／灾后 SAR 建筑损毁分割。问题：当前 Intact→Damaged 误报是否由超像素引起，下一版应该怎样形成区域、选择历史案例并使用检索证据。

补充证据后更新：用户随后提供固定 F/Q 的五路径结果，grid_probq 为 61.8381%，高于 pixel_grid 的 61.4194%。这支持现有 Q 的区域共享作用，排查优先级应转向实际表示／分类路径和 Memory 接法，详见[更新分析](/D:/software/dowmload/BRIGHT-master/notes/insights/20261010-region-constraint-evidence-and-memory-wiring.md)。下文原有的分区风险保留为条件性假设，不应据此优先重做 Q。

本报告核对本地当前代码、用户提供的正式 E0/E1 输出，以及论文、作者项目和作者机构材料。没有读取服务器上的模型张量或完整结果 JSON，没有新运行 450 张验证，没有重建实际 bank，也没有修改已有训练、审计代码及权重。数值结论限于用户提供的输出。

**判断：超像素可能造成一部分困难，但现有结果不能证明它是主要原因。应把“区域是否保留信息”“区域表示是否可检索”“历史证据是否适合修改当前判断”分别验证。推荐建立来源可追溯、保留软标签和质量信息的 Train 案例库，并让检索修正准确退回固定 J1。**

## 2. 这组实验到底证明了什么

用户给出的 formal_legacy_20261010_204130 运行：E0/E1 都完成 450 张，复现检查通过，E1 六项 immutable 都通过。以下 mIoU 是三个前景类别的平均，单位为百分比；差值用百分点。

| 分支 | 前景 mIoU % | Damaged IoU % | 相对 A1 的 Damaged 变化 |
|---|---:|---:|---:|
| A1 像素 | 61.686685 | 43.953841 | 0 |
| direct_region | 61.422202 | 42.907243 | -1.046598 |
| J1 | 61.637967 | 43.560570 | -0.393271 |
| J3 | 61.657357 | 43.580193 | -0.373648 |
| 标签余弦读出 | 58.772754 | 39.636222 | -4.317619 |
| 标签旧投影读出 | 55.859074 | 35.435339 | -8.518502 |

区域直接预测对 Damaged 有损失，但 direct_region 相比 A1 同时改变了分组、特征适配、注意力汇总、几何编码、分类头和输出投影，不能把 1.046598 个百分点全部归给分区 Q。它对 Destroyed 反而提高 1.056775 个百分点，说明区域路径存在类别间取舍，不能用单个总分描述成“区域全部无用”。

J3 相比 J1 的 Damaged IoU 增加 0.019623 个百分点，前景 mIoU 增加 0.019390 个百分点，但两者仍未超过 A1。单轮的小幅差值不能写成已验证的稳定增益，复现阈值也不是统计显著性标准。

直接读标签时，净新增 Damaged 假阳性为 1,730,261／3,167,763，其中真实 Intact 分别贡献 1,422,342／2,698,195，占约 82.20%／85.18%。这是像素，不是建筑数量。这个比例描述净增，不能改写为所有新增假阳性的占比。

更有区分力的现象：旧投影标签读出比余弦读出多得到 49,804 个净 Damaged 真阳性，却额外增加 1,437,502 个 Damaged 假阳性。这两个诊断沿用相同前端、Q 和库，主要改变检索空间。因此，纯粹“超像素切错了”不足以解释两者差异；检索及证据分布同样需要检查。

这些结果不证明旧投影训练在所有查询上更差，也不证明 Reader 浪费了所有标签支持。标签投票不是 Reader 的实际注意力，更不是可实现的性能上界。新版 hard-query 投影与有界门控没有包含在这次旧 J1/J2/J3 的 E1 成绩里。

## 3. 当前超像素到底怎样生成

当前代码是 [SwinLocalSuperpixelAttention](/D:/software/dowmload/BRIGHT-master/bda_benchmark/experiments/damageformer_srac_transformer_v1/model.py:74)。RGB 多层特征经过轻量 UNet++ 风格解码器，每个特征网格位置考虑周围 3×3 个种子。分配分数综合学习到的特征相似性、位置距离、预测建筑概率的相容性，并迭代更新区域中心。

输出 Q 是软分配，一个位置可以同时属于若干区域。建筑概率是软先验，不保证建筑与背景绝对分开，也不保证相邻建筑或不同损毁类分开。这一版不是旧 fourstage 分支的建筑／背景硬拆组；没有真实建筑实例 ID 输入，没有强制连通性后处理。GT 不进入生成 Q 的前向过程。

默认 stride=8 是特征网格上的种子间距，不能解释成原图 8 像素。如果实际网格为 256×256，默认对应约 32×32 个种子；真实配置和有效区域数必须读本轮 manifest 与张量，不能按默认值替代实测。种子格也不表示最终区域是固定正方形。

前端训练目前使用区域最终输出的 NLL 与 Lovasz，未单列 SSN 式标签重建或空间紧凑损失。[训练入口](/D:/software/dowmload/BRIGHT-master/bda_benchmark/experiments/damageformer_srac_transformer_v1/train_front.py:184)。这不等于“Q 没监督”：最终分类损失仍能通过可微路径训练 Q。

## 4. 为什么分区可能影响 Memory，又为什么只提高纯度不够

### 4.1 跨类别混合：案例卡片本身不清楚

一个区域覆盖部分 Intact、部分 Damaged，区域特征会混合两个来源。软标签保存这个混合是合理的；强行改成主类硬标签则会隐藏混合事实。还要区分前景／背景混合与 Intact／Damaged 混合，只有整体 purity 均值不够。

### 4.2 过细分区：标签纯，但线索可能不完整

BRIGHT 的标注由建筑多边形与建筑整体的灾后损毁属性组成。[数据论文 §2.2](https://essd.copernicus.org/articles/17/6217/2025/essd-17-6217-2025.html)。由此可推断：一栋 Damaged 建筑内的某个局部即使看起来完整，仍可继承建筑的 Damaged 标签。另一栋 Intact 建筑可能含有外观类似的局部。

所以，纯度 1 不代表该局部单独具有判断整栋建筑等级的充分信息。深层特征已有感受野和上下文，不能断言当前 token 完全缺少上下文；但仍应检查它是否保留了所需的建筑结构与灾后线索。粒度过细可能增加歧义，过粗可能跨建筑混合，不应默认越细越好。

### 4.3 软分配泄漏：硬边界图好看也可能混合

用 argmax(Q) 画图会隐藏其余分配权重。如果一个像素的第一候选是正确区域、第二候选跨越损毁边界，汇总与回写仍可能传播第二候选内容。应联合检查 Q 熵、跨类分配质量、软回投错误，不只看彩色分区图。

当前 soft_assignment_boundary 是相邻位置独立分配到不同种子的概率。分配越不确定，它也可能越高，不完全等于一条实际硬边界。[实现](/D:/software/dowmload/BRIGHT-master/bda_benchmark/experiments/damageformer_srac_transformer_v1/model.py:196)。不能只把这张热图解释为定位准确的建筑轮廓。

### 4.4 特征与答案的代表范围可能不同

[SuperpixelEmbedding](/D:/software/dowmload/BRIGHT-master/bda_benchmark/experiments/damageformer_srac_transformer_v1/model.py:271) 的主特征按 Q×注意力权重汇总；[region_targets](/D:/software/dowmload/BRIGHT-master/bda_benchmark/experiments/damageformer_srac_transformer_v1/common.py:160) 的标签按 Q 汇总，不包含这层注意力。

这可能使混合区域的特征强调一侧，而标签描述整个区域。它是需要量化的表示相容性问题，不是已确认的代码错误；注意力也可能恰好提升判别性。建议统计注意力前后各 GT 类占比变化，并做固定 Q 的均匀汇总对照。不能未经验证就把标签也改为注意力加权，因为那会改变监督对象。

最终 token 还加了区域面积、中心位置、空间范围等几何嵌入。因此检索相似度可能同时反映内容和几何，并非纯损毁相似度。先检查近邻类别与几何相关性，再决定是否让检索 key 单独使用内容、几何只交给 Reader。对已混合成单个 token 的旧缓存，不能假装无需重新提取就能精确分离这些成分。

### 4.5 即使区域和特征良好，仍然可能选错或用错支持

只有灾前结构像，并不足以推断灾后类别。Top-8 是可用候选中的排名，既不保证绝对接近，也不保证事件多样性。Softmax 会给较差的一组邻居分配总和为 1 的权重，标签投票因此可能很坚决地给出不可靠答案。必须保留绝对相似度和证据冲突信息，不能让归一化掩盖“库里没有合适参考”。

## 5. 先做不依赖 Memory 的区域质量诊断

所有诊断沿用已经通过 E0/E1 的 legacy/native 协议、同一 A1 和前端快照；保留 1e-5 复现门槛。旧 stage_diagnostics 入口曾使用严格数值设置，不能直接把那个入口的结果冒充当前正式协议结果。应复用其计算核心，在独立且兼容当前协议的诊断入口运行。

| 检查 | 固定什么／比较什么 | 能回答什么 |
|---|---|---|
| Q 的实际质量 | 当前 Q；按真实类、事件、区域大小分组 | 错误是否集中在混合区域、小目标、类别边界 |
| 带答案的分区压缩检查 | GT 面积分布先降到 Q 网格，再 Q 汇总、同 Q 回投 | 分区与软回投本身对类别信息的压缩有多大 |
| 同 F、同头的特征汇总 | 原特征 vs Q 均值汇总并回投，匹配非线性与插值顺序 | 不依赖检索时，区域平滑改变了哪些像素 |
| 匹配训练的像素／区域头 | 固定 F、Q，分别训练同预算的小分类头 | 损失更像头部适配不足，还是分组表示的限制 |
| 条件检索质量 | 相同库、排除规则，在不同 Q 质量桶内比较近邻 | 高质量区域是否也被检索引向错误类别 |

“带答案的压缩检查”具体为：有效标签 one-hot → area 降采样 → Q 区域标签分布 → 同 Q 回投 → 相同插值和 argmax。同时设置只 area 降采样再插值的分辨率对照。二者差异才对应额外区域压缩。忽略标签必须单独处理。

这是使用 GT 的离线诊断，不能作为模型成绩、推理组件或严格的 mIoU 上界。它很好但模型很差，并不自动证明 Memory 错；它很差，也不能证明保留像素分支的 J1 或残差 Memory 无法补偿。硬分区多数类可用于定义特定像素准确率的 oracle，但不能直接当作软分区、前景 mIoU、像素残差模型的共同上界。

已有可复用实现与统计说明见 [feature_core.py](/D:/software/dowmload/BRIGHT-master/bda_benchmark/experiments/damageformer_srac_stage_diagnostics_v1/feature_core.py:72) 和 [诊断 README](/D:/software/dowmload/BRIGHT-master/bda_benchmark/experiments/damageformer_srac_stage_diagnostics_v1/README.md)。该代码尚未替你完成上述新协议下的实际检查；其中匹配头训练、GT 标签压缩对照也不能被当成已有正式结果。

建议固定输出一组逐事件示例：灾前 RGB、灾后 SAR、GT、Q 硬边界与软不确定性、A1、J1、Memory 后预测，以及查询的 Top-8 来源和标签。覆盖救回 Damaged、正确 Intact 被改坏、持续漏判、没有发生变化四类。只看失败图会高估普遍性，只看好看分区会掩盖软泄漏。

若有原始建筑实例多边形，可以离线按实例检查区域是否跨楼；只有语义 mask 时，前景连通域只是实例代理，贴邻建筑可能连在一起。

## 6. 推荐的 Memory 建库方案

### 6.1 先确定版本，建立完整候选缓存

用冻结的特征提取器和 Q 处理全部 Train。当前 [build_memory.py](/D:/software/dowmload/BRIGHT-master/bda_benchmark/experiments/damageformer_srac_transformer_v1/build_memory.py:95) 已经保存逐图区域缓存，可以复用。

缓存分三种复用情况：

- 只改选样：可从同一完整 Train 缓存重新选 bank。
- 只改检索投影：原始 token 与标签可复用，查询和 bank 两侧都更新检索 key。
- 改 Q、前端、token 汇总或表示：重新提取完整 Train 候选与查询缓存，重建 bank，并训练匹配的检索器／读取头。不能只换验证 Q，再对旧库评估。

缓存、bank、projector、Reader 均记录匹配的特征与分区版本、源样本 ID、配置、权重摘要。原 bank 留作 B0 对照，新增版本单独保存。

### 6.2 一条记忆保存什么

| 字段 | 含义与使用 |
|---|---|
| 原始区域特征 | 保存证据内容，使更换 projector 不必重新跑前端 |
| 检索 key | 同一个 projector 将查询和库映射到可比较的空间 |
| 四类软标签 | 保存区域的真实标注组成；主类仅用于配额分桶 |
| 区域质量 | 标签纯度、有效标签质量、区域质量／面积、Q 熵等；明确区分 GT 得到的支持质量和可在查询推理时获得的质量 |
| 来源 | 事件、图像、区域 ID；跨事件排除、去重、回看案例 |
| 几何与上下文 | 当前已有的几何；扩展上下文需要另做表示实验，不能声称旧 token 已包含新的字段 |
| 版本信息 | 前端、Q、建库规则与 projector 版本 |

库内训练样本标签与纯度已知，可以参与支持质量计算。验证查询的真实标签和真实纯度只用于离线诊断，不能输入检索器或门控。

### 6.3 参考库与查询练习集分开

**参考库**优先保存标注关系清楚、有效覆盖足够且外观多样的案例，同时保留有判别价值的困难 Intact 与 Damaged。标注纯度高与 J1 预测正确是两件事；不能把“只保留 J1 已经会的题”当作可靠性定义。

**训练查询集**保留普通区域、困难 Damaged、混合区域，以及“真实 Intact 且 J1 原本正确，但跨事件标签证据倾向 Damaged”的风险查询。风险判定与采样只用 Train；更严格的校准可在 Train 内按图像／事件留出。训练集上的 J1 预测不自动等同于 out-of-fold 预测。

混合区域可用软标签与适当监督权重训练查询，但不应被包装成纯类别参考。若增加低纯度上下文支持，应标记类型并单独对照，不宜让它与核心分类参考拥有相同解释。

### 6.4 保持容量，先改选择质量，再改多样性

当前建库按事件×主类做随机优先级抽样，默认每桶最多 64 条，默认 min_purity=0；0.8 是旧 metric 训练筛选的重要阈值，不能误写成所有原 bank 成员都满足 0.8。[建库参数](/D:/software/dowmload/BRIGHT-master/bda_benchmark/experiments/damageformer_srac_transformer_v1/build_memory.py:33)。实际实验取值以 manifest 为准。

推荐分开测试：

1. B0：原 bank。
2. B1：保持容量、事件和类别配额，单独测试支持质量筛选／排序。
3. B2：在明确的候选集合内单独测试多样性选样，例如选真实样本中的代表点、限制同图高度重复区域，而非每类只留一个均值中心。
4. 只有 B1/B2 各自有证据，再组合。若某桶高质量样本不足，显式报告数量；不要复制样本补满，或不报告地同时改变配额。

0.8／0.95 可作为分析分桶，不应凭经验直接宣布某个阈值最佳。先检查过滤后 Damaged、Destroyed 及稀缺事件是否仍有覆盖。支持事件多样性也要兼顾相关性，不能为了凑不同事件塞入很不相似的参考。

多代表的动机可参考 [ProtoSeg，CVPR 2022](https://arxiv.org/abs/2203.15102) 和[作者代码](https://github.com/tfzhou/ProtoSeg)。它同时学习表征与原型，不能推出对冻结 token 做聚类必然胜过真实样本库。

## 7. 查到参考后怎么用

当前 [select_ids](/D:/software/dowmload/BRIGHT-master/bda_benchmark/experiments/damageformer_srac_qmetric_v1/metric.py:535) 是全库投影余弦 Top-K，排除同事件、同图像，不输入查询 GT。下一版第一轮仍保持 Top-8，避免同时改变容量和邻居数。

检索训练应同时解决两种混淆：困难 Damaged 要靠近可信 Damaged、区分相似 Intact；容易被误导的 Intact 要区分相似 Damaged。已有对比学习无需再作为“新模块”重复添加，改动重点在查询分布、负例与软标签目标。[ReCo，ICLR 2022](https://arxiv.org/abs/2104.04465) 的困难查询和混淆负类采样提供依据；[作者实现](https://github.com/lorenmt/reco/blob/main/module_list.py#L65)不直接包含这里的“J1 正确但受 Memory 误导”定义，这部分是本项目的适配。

使用证据建议保留固定 J1 的像素 logits：

\[
z_{\mathrm{new}}(i)=z_{\mathrm{J1,fixed}}(i)+\sum_r Q_{ir}\,g_r\,\Delta_r.
\]

这里写的是简化后的同网格回投关系，实际实现需要匹配现有插值与分辨率。修正有界，门控观察绝对相似度、支持标签冲突、有效支持质量、来源多样性与 J1 状态。全部 gate 为 0 时，新增项应严格为 0。由于 Q 软重叠，仅关闭一个区域不代表相应像素不会受到其他区域修正。

当前 [GatedMemoryCorrection](/D:/software/dowmload/BRIGHT-master/bda_benchmark/experiments/damageformer_srac_hardquery_memory_v1/reader.py:165) 已实现有界修正、零初始化、缺失支持拒绝和 force_off，不需要把这些说成尚未实现的创新。但连续 sigmoid gate 不保证对每组有害的非空支持输出精确 0；若要主动硬拒绝，还需在 Train 内校准明确的接受规则并验证。全局强制关闭的恒等性与自动选择性拒绝的有效性是两个不同检查。

下一轮训练重点是自然出现的非空误导支持：J1 原本正确的 Intact 应尽量保持；J1 漏判的 Damaged 应保留可获得的救回。随机构造错配支持可以作为额外干预，但必须与正常支持区分，不能只依赖容易识别的随机噪声。support dropout 主要训练缺失参考，不能替代这类拒绝训练。

[Adaptive kNN-MT，ACL 2021](https://aclanthology.org/2021.acl-short.47/) 根据距离与标签相关信息调节近邻数量和融合权重；[作者代码](https://github.com/zhengxxn/adaptive-knn-mt)。可借鉴自适应使用证据的机制，原任务与这里不同，软混合本身不保证严格拒绝。

## 8. 发现区域确实有问题之后，怎样改 Q

先固定 A1、训练预算、损失与其他设置，单独比较一种分区变化。规则网格、SLIC、当前学习 Q 可以作为控制组，但应匹配有效区域数量、处理分辨率和后续头部训练；不能只在一个已训练头上换掉 Q 后，就宣判另一分区方法更差。

- **跨类别混合突出**：考虑 Train 标签重建辅助损失，兼顾空间紧凑性；GT 只作为训练目标。参考 [SSN，ECCV 2018](https://varunjampani.github.io/ssn/) 的可微任务相关分区，以及 [SpixelFCN，CVPR 2020 作者代码](https://github.com/fuy34/superpixel_fcn/blob/master/loss.py)的语义与位置重建。它们不是 Memory 方案，而是检验和训练 Q 的依据。
- **小建筑在当前网格被压缩**：先区分输入到特征网格的降采样损失与种子过稀。仅将 stride 从 8 改为 4 不会恢复特征网格之前已丢失的细节，还会把名义种子数量提高约四倍。需要实测有效区域数、计算和检索预算。
- **边界较好但局部语义不足**：测试当前局部 token 加预测建筑区域／邻域上下文，避免直接把超像素当建筑实例。预测建筑区域也可能漏检或合并，需要与固定局部方案匹配对照。
- **软泄漏明显**：检查熵与错误的关系，再测试温度、紧凑性或分配正则。低熵不必然正确，不能只优化成看上去更清晰的硬分区。

任何 Q／token 改动完成后都必须重新建立匹配的 Train 库。验证集真实边界或真实建筑实例只能用于诊断，不能成为部署时分区的输入。

## 9. 建议的最小实验次序与决策

| 阶段 | 主要变量 | 下一步依据 |
|---|---|---|
| S0 区域诊断 | 固定原模型，不训练 | 找到损失集中在分辨率、Q、表示／头部还是检索 |
| S1 条件性修 Q | 仅一种 Q 改动，并训练匹配头 | 只有区域信息保留与最终分类改善，才进入新的建库分支 |
| B1／B2 建库对照 | 固定选定 Q 与 token，分别改变质量或多样性 | 排除后覆盖、标签检索精确性是否提高 |
| R1 风险查询训练 | 固定 bank 和 Reader，改变查询／负例训练 | 正确 Intact 的检索误导是否降低，困难 Damaged 支持是否保留 |
| U1 使用与拒绝 | 固定检索，匹配无门控／门控预算 | 最终净救回是否超过误改代价 |

现有六组“query／bank／hard × ungated／gated”仍是有效的计划内对照；当前 E1 不能替代它们。上述 S0 可以先行，不必等新训练完成；不要未看结果就同时换 Q、库、投影与 Reader。

每轮至少保存四类 IoU／Precision／Recall、前景 mIoU、逐事件与逐图混淆矩阵、相对固定 J1 的救回／伤害／假阳性、检索相似度与支持组成、接受率、时间和显存。保留 A1 对照，避免只在已受损的 J1 上取得小回升。

“真实 Intact 新增 D 假阳性”不全等于“原来预测正确的 Intact 被改坏”。用 GT×old×new 表时，精确的正确 I→D 为 t[1][1][2]，并以 J1 正确的 Intact 像素总量归一化。按事件报告，避免大事件决定全部结论。

若要声称稳定收益，再对候选胜出方案做多随机种子和按图像／事件配对的不确定性分析；不能把数百万相关像素当作独立实验样本。阈值及采样规则先在 Train 内确定，Val450 用于既定比较，Test 不参与选择。

## 10. 研究落点、难度与可执行题目

已有 SRAC、SSN、PMN、ReCo、ProtoSeg 等覆盖超像素、原型记忆、困难对比与多原型思路。“超像素＋Memory”或“加入一个 gate”本身不足以证明创新。本项目更有价值的落点，是用匹配对照确定跨事件历史证据在哪类区域失效，以及如何改善检索和拒绝之后的最终像素收益。

1. **面向 BRIGHT 跨模态建筑损毁分割的区域信息保留诊断与检索记忆构建**：借鉴 SSN／SpixelFCN，比较 Q 压缩、匹配头和检索质量；中等成本。预期贡献是可定位的信息损失分析与针对性的分区训练，风险是纯度改善并不转化为损毁判别。
2. **面向跨事件 Intact–Damaged 混淆的风险查询检索学习**：借鉴 ReCo，加入 Train 中基线正确但检索误导的查询；较低改动成本。以原投影、现有 hard-query、风险查询三组匹配对照，预期贡献是兼顾漏判恢复与正确样本保护，风险是过度保护使 Memory 失去作用。
3. **区域质量条件下的选择性历史证据修正**：借鉴自适应 kNN 使用机制，将支持质量、查询可观测质量与固定 J1 结合；中等成本。比较同检索下有无选择性修正，预期贡献是可解释的救回／伤害权衡和拒绝能力，风险是门控记住事件特征或仅复述基线置信度。

这些题目是可检验研究方案，不是已经获得的贡献或成绩。当前最小行动是完成 S0 并对现有新 Reader 做匹配实验，由证据决定是否需要重训 Q，再形成最终库。
