本说明整理对话中用户已经报告的结果。本包没有访问远程 GPU 或重新读取服务器原始 result.json，因此这些数字的来源状态是 **user-reported，未在本地重新验证原报告**。`reported_results.csv` 保留该标记。

- 1500、2000 步 Test878：本说明不补造数字，不把中途停止的部分结果当成完整测试。

- 多种子：尚无可汇总的独立重复结果；图中不画误差线、不报告显著性。
- 已完成的检查点和通过的历史评估值得保留；后来某次运行失败不自动使所有旧数据失效，但也不能作为执行环境已恢复可靠的证据。

每个正式结果行应绑定：代码版本、实验组、seed、检查点 SHA256、步数、数据划分、样本名单哈希、评价脚本版本、完整性状态、原 result.json 路径。不能把不同节点的类别 IoU 拼在一行。

## 2. 过去的实验分别回答了什么

| 实验／工作 | 原本问题 | 可以支持的结论范围 | 不能替代的证据 |
|---|---|---|---|
| Q／区域汇总与 SAR→Q 对照 | 区域组织、额外 SAR 线索是否有价值 | 需以各自同协议结果和对应对照为准；本包没有这些实验的原始数值 | 不能由当前 E−Grid 反推 Q 单独有效 |
| A/B/C/D | 空间／soft 分槽和图内／历史支持的差异 | 比较区域分槽与支持来源的组合 | 不直接回答单槽对双槽，因为这些组并非单槽控制 |
| E/F/B/D | 单槽／双槽 × 图内／历史支持 | 查看结构与支持来源的条件差值 | 不把所有差值叠加为互相独立的因果贡献 |
| D/R | 父区域相似检索对比随机合法候选 | 粗检索候选选择的额外价值 | R 仍有可训练 attention，不能称完全随机读取 |
| D/L | 正确特征—标签配对对比受限置乱 | 配对信息的额外价值，取决于置乱强度 | 不能等同完全移除历史标签；事件先验仍保留 |
| D/N | 标签嵌入开启／关闭 | 同样视觉支持、同样 IDs 下标签路径的价值 | N 不是关闭 Reader；目前六分支结果未包含 N |
| Control/Anchor | 原目标对比额外 Grid KL | 全局 KL 是否给已有系统增加收益 | 不直接证明 Memory／检索是否有效 |
| 固定 Train 诊断、候选和 Reader 审计 | 输入信息、读取信息、预测纠错是否吻合 | 形成具体改进假设与机制证据 | 注意力／标签质量变好不等于最终性能改善 |
| NLL 校验、路由观测、恢复、Sanitizer | 执行是否可靠、错误发生在哪个环节 | 工程运行和数据完整性证据 | 没有损毁识别提分含义；不能写成方法性能消融 |

历史训练已达到 2500 步。补评估是读取已有检查点；本轮新方法应写入新实验目录，并显式标记新配置，不能把修改后的结果续写成未改配方的历史轨迹。

## 3. 当前“区域设计”具体是什么意思

设像素／特征格点 p 到父区域 r 的软归属为 Q[p,r]，满足非负且对候选区域求和为 1。父区域池化汇集局部特征，unpool 再把区域上下文送回像素网格。

soft 双槽概念上为：

```text
背景角色槽权重 = Q × (1 − 建筑概率)
建筑角色槽权重 = Q × 建筑概率
```

它分离的是背景／建筑角色，并非完好／受损／毁坏的三个损毁等级。槽是软分配的上下文容器，不能展示成严格的建筑实例轮廓，也不能把两个槽命名为两种 GT 损毁类别。

父区域 T128 在两个子槽中共享；子槽另有 F256 汇总、角色嵌入和占比嵌入。检索先在父区域层面筛候选，两个查询槽共享父候选，再由可训练 attention 读取不同槽信息。

可能有益的机制包括减少背景与建筑特征混合、汇集区域上下文、用残差适配纠正原始 Grid。但这些都是与架构一致的解释，**尚未被 E−Grid 单独隔离验证**。E 同时包含单槽表示、图内 Reader、自身支持和可训练后端。称它为“仅分类头训练”会错误缩小对照范围。

## 4. 当前数值应怎样解释

单位为百分比（mIoU4）或百分点（两者差值），不混写相对百分比。

| Test878 步数 | Grid | E | B | D | E−Grid | D−Grid | D−B |
|---|---:|---:|---:|---:|---:|---:|---:|
| 500 | 68.5259 | 68.7570 | 68.7979 | 68.8252 | +0.2310 | +0.2993 | +0.0272 |
| 1000 | 68.5259 | 69.0468 | 69.0562 | 69.0753 | +0.5209 | +0.5494 | +0.0191 |
| 2500 | 68.5259 | 69.0060 | 69.0210 | 69.0326 | +0.4801 | +0.5067 | +0.0116 |

2500 步的结构对照：

| 差值 | 数值（百分点） | 对应问题 |
|---|---:|---|
| B−E | +0.014991 | 图内支持条件下双槽相对单槽 |
| D−F | +0.018070 | 历史支持条件下双槽相对单槽 |
| F−E | +0.008558 | 单槽条件下整套历史支持相对图内支持 |
| D−B | +0.011637 | 双槽条件下整套历史支持相对图内支持 |
| D−R | +0.003415 | 相似父候选相对随机合法父候选，之后均有 attention |
| D−L | −0.000065 | 正确标签配对相对受限置乱标签配对 |

结论应写成“本次运行观察到小幅数值差异”，不能写“稳定／显著增益”或“完全等价”。D 与 L 接近也不能单独证明模型没有利用标签：受限置乱可能很弱，且重新训练的模型可能适应这种扰动。

算术上，D−Grid=(E−Grid)+(B−E)+(D−B)。这个恒等式可以帮助阅读表格，**不是独立因果贡献分解**。不能计算 E−Grid 除以 D−Grid 后宣称“某模块贡献了约 95%”；这些模型经过独立训练，存在交互与补偿。

1000 步的 D 与 2500 步的 D 来自同一轨迹，不能作为独立样本验证稳定性。已被多次用于设计判断的 Test 应标明探索性使用；后续配置和检查点规则由 Train／Val 决定。

## 5. Val1500 单独说明了什么

下表来自此前 Val450 完整混淆矩阵的计算／对话汇总，不能拿这里的约 70.7% 与 Test 的约 69.0% 比较方法优劣。

| Val450 指标，1500 步 | Grid | D | 解释 |
|---|---:|---:|---|
| 建筑二分类 IoU | 82.5397% | 83.2033% | 合并三个前景类别后，建筑定位改善 |
| 建筑召回率 | 90.0048% | 90.7720% | 建筑漏检减少 |
| 建筑精确率 | 90.8689% | 90.8914% | 基本接近 |
| 受损 IoU | 44.1301% | 44.1296% | 等级判断未随定位收益同步改善 |
| 毁坏 IoU | 65.6755% | 65.5670% | 毁坏召回改善，同时精确率下降 |

由四类 argmax 预测合并得到的建筑指标，与直接对建筑概率阈值化得到的指标可以不同，必须说明计算口径。

已报告的关键净变化：

- 建筑→背景：6,924,736 → 6,393,261，净减少 531,475。
- 背景→建筑：6,265,908 → 6,302,190，净增加 36,282。
- 受损→完好：2,205,141 → 2,203,006，主要等级错误几乎不变。
- 其他类别→毁坏：748,821 → 967,583，净增加 218,762。

这些是混淆矩阵总数的差，不是已经逐像素追踪的“纠正／误伤”数量。只有匹配同一图像、同一像素的两组预测，才能分清具体纠正了哪些错误、制造了哪些新错误。

与“背景／建筑 soft 双槽”的设计方向一致，目前能提出“该设计更有利于定位而非等级细分”的假设；但 D 相对 Grid 同时改变多条后端路径，所以它还不是双槽机制的独立因果证据。

## 6. 如何验证区域贡献，而不是仅验证整套模型

优先补匹配的无 Reader 对照：保留像素、父区域、查询槽、Grid 概率和原融合头宽度，从训练开始将 Memory context 置零。它回答“区域后端之外，支持读取带来多少收益”。评估时临时置零仅测依赖性，不等于重新训练的消融。

若论文还要进一步主张“区域设计本身有效”，可以按预算追加以下结构控制：

| 条件 | 父区域路径 | 查询槽路径 | 支持读取 | 用途 |
|---|---|---|---|---|
| Pixel/Base adapter | 零输入 | 零输入 | 零输入 | 像素＋Grid 的匹配残差适配基线 |
| + Parent | 开启 | 零输入 | 零输入 | 检验父区域上下文的增量 |
| + Query slot（即当前建议的无 Reader） | 开启 | 开启 | 零输入 | 检验查询槽分支的增量 |
| + Local reader | 开启 | 开启 | 图内 | 检验图内支持读取 |
| + Historical reader | 开启 | 开启 | 历史 | 检验跨图像支持方案 |

尽量保持融合层宽度、初始化、优化器、样本顺序和更新预算一致，并报告实际参与优化的参数量。置零路径虽然保留结构参数，但实际可用表示／有效容量仍会变化；不要把所有差异解释成几何组织本身。若要声称 Q 的空间组织优于任意汇总，还需一个规则网格／打乱归属等明确且公平的组织对照，不需要在本轮立刻全部扩展。

一次只选与论文主张直接相关的缺口。当前首要缺口是无 Reader 基线；其余用于后续解释，不是要求一次重跑全矩阵。

## 7. 推荐如何在论文和汇报中展示

1. **结构图：** 标出父区域 Q、建筑／背景 soft 双槽、父级粗检索、槽级 attention、标签进入 Value、本地旁路。将 GT 到训练损失／Train 库的连线与推理输入分开。
2. **总体性能表：** 固定划分、固定节点；逐行报告四类 IoU、mIoU4、前景 mIoU3、seed、完整性。精度统一，差值用百分点。
3. **结构差值图：** 大尺度看 E/B/D 相对 Grid，独立小尺度看 B−E、D−F、D−B、D−R、D−L。注明横轴尺度不同，避免小差值被视觉放大成大收益。
4. **类别误差图：** 行为真实类别、列为预测类别的行归一化混淆矩阵；另画 D−基线的混淆变化。每行注明支持像素数，不能把背景数量主导的总准确率作为唯一证据。
5. **配对可视化：** 预先规定代表图选择规则；同时展示改进、退化、基本不变样本。受损→完好和非毁坏→毁坏用不同颜色，注意力热图仅作为机制辅助。
6. **机制表：** 候选类别覆盖、读取标签分布误差、固定模型标签干预前后的概率变化、最终净纠错。仅“读得更对”而最终性能无提升，必须如实报告。
7. **多种子表：** 至少对准备主张的核心对照给出每个 seed 的配对差值和均值／离散程度。三个 seed 是初步稳定性检查，不足以自动宣称统计显著。

逐图 bootstrap 应成对重采样两方法的同一批图，并重新聚合混淆矩阵计算 mIoU。相邻图像／同事件相关时，可补事件级汇总或按事件成簇重采样并说明事件数限制。不能把数亿像素当作独立重复，也不能把各图 IoU 平均当作全数据集聚合 IoU。
